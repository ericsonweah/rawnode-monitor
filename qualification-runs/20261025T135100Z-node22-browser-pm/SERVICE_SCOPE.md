## Storage and transport handoffs

### Redis bridge and leadership

Reviewed inputs: `package/src/cluster/RedisMonitorBridge.js`, `LeaderLease.js`, `MonitorClusterEnvelope.js`, and runtime cluster wiring. Direct bridge defaults: channel `rawnode:monitor:cluster`, namespace `default`, secret null,2,097,152-byte message limit. Runtime derives namespace from `service:environment`, source from explicit instanceId or host:pid, and secret from cluster.secret or ingestSecret. Cluster is disabled by default; default mode is standalone. LeaderLease requires an injected `sendCommand` interface and executes ownership-checked Lua through EVAL for acquire/renew/release; pub/sub requires `subscribe(channel,handler,{serial:true})`, optional subscription readiness/unsubscribe, and publish. No Redis implementation is bundled.

Later configuration must supply an approved client/version and disposable server/database/namespace, unique service/environment/instance IDs, a unique channel and leaderKey, `cluster.enabled:true`, a reviewed non-standalone mode, and disposable signing material. Validate whether the client's returned subscription shape matches this contract before enabling runtime integration. Review EVAL/SET/INCR/GET/PEXPIRE/DEL and pub/sub ACLs, TLS/authentication and expiry behavior. Existing late-subscribe/ready and late-lease tests prove injected lifecycle behavior only.

Expected evidence: actual round-trip envelopes, wrong namespace/signature/expired/oversized rejection, self-message exclusion, independently observed recipient counts, unsubscribe/readiness failure, and no resurrection after close. A live leadership lane additionally needs competing task-owned participants, acquisition/fencing, renew/loss/release under approved faults, no successor deletion, and receiver-side behavior under lost leadership. Envelopes carry a nonce but current verification does not maintain a replay cache; do not claim duplicate suppression or exactly-once delivery. Redis pub/sub admission is not durable storage.

Cleanup: unsubscribe only bridge-owned subscriptions; release only the verified owned lease; remove only run-namespaced fence/test keys if separately allowed; close test-created clients only after borrowed-client survival assertions. Do not flush a database, delete shared keys or stop an ambient Redis process.

### RawMongo and durable/composite storage

Reviewed inputs: `package/src/storage/RawMongoTelemetryStore.js` and `createTelemetryStore.js`. RawMongo is injected as `database.collection(name)`, `database.db().collection(name)` or `database.connection.collection(name)`. Writes use insertMany/bulkWrite/insertOne; reads need find with appropriate sort/skip/limit/toArray and optionally countDocuments; prune uses deleteMany. No Mongo driver, index creation or live durability test is supplied by this interface. Documents receive createdAt/expiresAt; those fields alone do not install a TTL index. Default prefix `monitor_`, retention30 days, batch1,000 and direct query bound10,000.

Later input: exact RawMongo/client/server identities, authorized disposable database, unique collectionPrefix, authentication/TLS/write concern/read concern/replication and index policy. Explicit config: `storage:{enabled:true,driver:'rawmongo',required:true,collectionPrefix:<owned-prefix>,retentionMs:<approved-duration>}` plus the injected database. A composite lane must also name `drivers`, queryStore and durable requirement; approve any file root separately. Avoid optional memory fallback in a test claiming durable storage.

Expected evidence: complete and partial write failures, actual acknowledged counts, independent query/readback after reconnect, per-kind partition/global sort/filter/offset bounds, tenant/trace filters, duplicate-ID handling, retention/prune/TTL behavior under the chosen index policy, and failure propagation for required storage. State the actual persistence/replication level observed, not just Monitor admission. Cleanup closes only the adapter's owned work (its close does not close the borrowed database), proves database usability, and removes only the named test collections under explicit authority.
