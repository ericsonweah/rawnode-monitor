# Node 22.0.0 mocked timer compatibility

The exact October 25 archive was extracted without changes, hashed against `69e756daa6d127ca919acef8f430998a35bf1217cb2491d20b11dd77a1e908f7`, and executed with the official Node 22.0.0 Darwin x64 binary. The first restricted attempt had 77 passing cases and 20 failures: 18 loopback permission failures plus two mocked timer failures. A permission-approved loopback run selected all 97 cases and produced 95 passes, two failures, zero skips/cancellations/todos. Both raw attempts remain in `../node22-baseline-restricted/` and `../node22-baseline-loopback/`.

The two failures were the existing modeled inspection cases in `test/studio-actions.test.mjs`: preserving trace/incident/diagnostics details, and preserving filters/focus/expanded details. Studio calls `clearInterval(poll)` while its initial polling handle is null. This is valid natively and in the browser. Node 22.0.0's experimental mock instead dereferences the null or undefined handle and throws `Cannot read properties of null (reading 'priorityQueuePosition')`.

`../scripts/mock-timer-probe.mjs` records the boundary separately from Studio. On Node 22.0.0 native cancellation accepts both null and undefined, while mocked cancellation rejects both. On retained Node 24.21.0 both native and mocked cancellation accept them. A nullish-handle fixture adapter restores that no-op contract. Positive controls prove that an active interval still ticks three times, a canceled interval never ticks, and cancellation prevents further active ticks. Probe outputs are `mock-timer-node22.txt` and `mock-timer-node24.txt`.

The only package correction is a nine-line `mockIntervals(t)` test helper and two call replacements in `package/test/studio-actions.test.mjs`. It delegates every non-null handle to the real mocked cancellation function and restores timer mocks and the original native function during test teardown. Runtime code, assertions, case names, and test selection remain unchanged. No failure is suppressed and neither the engine declaration nor polling behavior changes. The seven October 25 regressions reside in other untouched files.

After correction, all six tests in that file pass independently on both runtimes (`studio-actions-node22-after.txt`, `studio-actions-node24-after.txt`). The complete Node 22 source suite passes 97/97 with zero fail/cancel/skip/todo (`../node22-source-after/commands.json`). Build checks 112 JavaScript files and 29 exports; the basic example, strict root/all-export declaration checks on TypeScript 5.9.3 running on Node 22.0.0, and expected publication refusal also pass. The final artifact and fresh consumer receipts are recorded separately and must identify the corrected bytes.

The CLI `--test-timeout` flag is supported by Node 22.0.0 and was used successfully. No harness flag removal was needed. Official version-specific reference: https://nodejs.org/download/release/v22.0.0/docs/api/cli.html.
