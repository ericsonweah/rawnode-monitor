# External token-session wrapper review

This is **HTTP-only server/harness evidence**, not a native Studio browser pass, native Cancel result, EventSource/polling observation or browser-storage inspection. It used the final offline-installed Monitor at `/private/tmp/rawnode-monitor-qualification-INTlq3/installed/node_modules/@rawnode/monitor`, bound to archive SHA256 `a749983cc32e7ed9df10088dbe671fc4c6a3d47ed9a22da8a9d48d1e789c2615`. No package file was edited. Runtime was `/usr/local/bin/node` v24.21.0, macOS darwin x64; each probe started its own loopback fixture and closed it through stdin.

## Finding and authorized correction

The original external wrapper applied session/bearer checks through the Studio controller authorizer. The packaged fixture's synthetic empty/error mode and external fail-next response can return before controller dispatch. In a fresh token-mode session this let a no-bearer empty traces request return synthetic HTTP200 and a no-bearer incident POST receive synthetic HTTP503. Neither changed the incident or silence state, but those responses could falsely suggest protected-mode acceptance. This is a qualification-harness ordering defect, not evidence of a bypass in the packaged controller itself.

The parent authorized a correction after reproduction. The external token wrapper now calls manager authorization before any API mode/failure overrides. It caches the manager decision by request and mutation mode, so the later controller uses the same decision and rate-limit accounting occurs once. Loopback socket/Host, origin/CSRF, session, bearer and manager rate-limit checks remain active. Local-mode behavior and native prompt delegation were not changed. Running sessions retain their loaded version; the correction applies to new sessions.

A further focused review found that the custom authorizer classified API requests using raw `req.url`, while routing parsed the pathname. An absolute-form HTTP request target with a valid host session could therefore receive HTTP200 without a bearer. Attempt05 reproduced this external-wrapper defect. The authorizer now parses the same pathname as routing; attempt06 verifies401. Normal browser request behavior is unchanged. This is not a package controller change.

## What passed and what remains native

The corrected wrapper rejects shell, packaged assets and instrumentation assets without its host session. Missing/wrong setup code gets403; the exact synthetic setup code establishes an HttpOnly, SameSite=Strict session cookie, scoped to `/`, with no persistent expiry. This fixed local operator code is demonstration-only, not a production authentication design. HTTP loopback is the reason this disposable cookie lacks Secure. It is a host session credential separate from Studio's in-memory bearer token.

With the session, shell HTML declares token-required and exposes no bearer literal. Correct bearer without session, session without bearer, wrong bearer and a query token all fail401. The session plus correct bearer succeeds200. A native-stream request without bearer fails401, consistent with the supported token-mode polling contract; HTTP cannot prove the actual browser selected polling. Cross-origin reads, cross-site fetch metadata, non-loopback Host and cross-origin mutation fail403. Independent state checks verify no denied CSRF mutation changed incident/silence/request state. Synthetic seeded/empty/error/fail-next responses are now downstream of authorization, and the ordinary limiter remains enforced.

Source review confirms packaged Studio fetches use the authorization header, public client snapshots omit the token, native token-required mode does not construct EventSource, and packaged client source contains no localStorage/sessionStorage access. The probe verifies the served client has no persistent-storage calls or embedded bearer literal. Actual token entry, recovery, polling, reload/disposal and browser storage observations still require the separately recorded native token session.

## Logging review and boundaries

Request logs retain method, pathname, session/case and only boolean bearer/session presence. They omit authorization/cookie values and query strings. Actual probe logs were scanned for the synthetic bearer, randomized session-cookie value and query-token marker; none was present. Record files use0600 and the newly created evidence directory0700. Child input receipts and close receipts identify fixture/package/runtime and final clients/listeners without retaining credentials.

Browser event input is bounded to65,536 incoming bytes and intentionally trusts this controlled synthetic fixture; native prompt text/results and selected UI text/errors may be recorded. It is not a general-purpose secret-redaction boundary, and its broad comment that tokens/storage contents are never recorded must be understood as the selected event schema and synthetic-data discipline, not arbitrary-input sanitization. Client observation records storage key names only and a token-free public snapshot. Do not enter real credentials or arbitrary sensitive text into this fixture. This HTTP probe did not claim to test browser-event payload redaction or persistent browser state.

Every successful fixture was closed through supported stdin, produced a closed receipt with listening=false and clients/listeners0, exited naturally0, and returned ECONNREFUSED on a subsequent owned-port probe. Only these task-owned servers/children were touched. No external service or notification was contacted.
