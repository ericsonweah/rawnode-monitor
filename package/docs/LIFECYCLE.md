# Lifecycle and ownership

Construction registers definitions and internal listeners. Import is passive. Explicit `start()` initializes the store, plugins and integrations, then configured collectors, retention, SLO/alert timers, initial collection and health checks. Profiles may freeze definitions after startup; register application instrumentation first. Concurrent starts share one startup operation. A close request cancels startup before additional stages start. Failed startup performs cleanup and leaves the runtime terminal.

`close({timeoutMs, flush, throwOnError})` stops owned periodic work immediately, aborts collection/startup signals, and starts independent component cleanup. Pipeline close flushes admitted work unless `flush:false`. Cleanup attempts are bounded. `throwOnError:true` reports failures after making the lifecycle terminal; default close records completion without claiming that a non-cooperative user callback stopped. `flush({timeoutMs, signal, throwOnError})` waits for plugin notification draining and pipeline delivery. Unresolved third-party/user callbacks may continue using their own resources; supply abort-aware callbacks. No library can cancel synchronous blocking JavaScript.

An instance cannot be restarted after close, including `start({restart:true})`; that formerly misleading source option now returns `MONITOR_CLOSED`. Create a new instance or replace it in your owning service. `MonitorManager.create(...,{replace:true})` rejects replacing a live owned runtime; close the old runtime first. The original code's single-use component closures made in-place restart incomplete.

Metric and resource collections coalesce at runtime level. Observable collectors retain their active callback until settlement to prevent overlapping stuck work; a deadline reports timeout and discards late observations. Health and resource checks expose AbortSignal. Synthetic checks enforce concurrency, bounded queued waiters, deadlines and removal identity; unregistering or replacing a check cannot resurrect an old timer/state. Pipeline sinks have bounded concurrency and deadlines; unknown timed-out writes are not retried automatically because duplicate side effects are possible. Explicit failure retries remain bounded.

Studio and PM bridges are separately owned. Close Studio before the HTTP server, and close bridges before dropping their targets. Studio closes SSE clients, heartbeat timers and its signal listener. The browser `mountMonitorStudio(root)` returns `refresh`, `navigate`, `snapshot` and idempotent `destroy`. Remounting the same root destroys its preceding handle. Destroy aborts pending fetches, clears polling/debounce/toast timers, closes EventSource and removes global listeners.

Registry definitions and direct low-level objects are trusted application controls. A snapshot may intentionally retain bounded records after close for diagnosis. Dropped pipeline references and removed metric series no longer retain payloads. Shutdown never signals application processes or registers a daemon.

Health replacement invalidates the name's TTL cache. Registration disposers are identity-bound; explicit `unregister(name)` still removes the current registration. An old pending check cannot cache a result for its replacement. Resource replacement clears its latest record and suppresses retired collection events as well as cache updates.

Direct `HttpJsonExporter.close()` closes admission synchronously, aborts active HTTP requests and retry waits, checks compression/split continuations, destroys its owned agent, and waits for admitted exports to settle. A new export after close returns `false`; an interrupted admitted export rejects with `MONITOR_EXPORTER_CLOSED`. Its statistics count acknowledged 2xx chunks. A failed split export can have acknowledged earlier chunks, and an aborted request may already have reached its receiver; shutdown does not undo remote delivery. Runtime cancellation is additional to the exporter's own lifecycle.

`JsonlTelemetryStore.writeMany()` registers the full operation before initialization yields. `flush()` waits for operations already admitted when called; it does not exclude later writes. `close()` stops admission immediately and drains all earlier operations across signal kinds. Repeated close shares that drain. Write errors remain observable to the write caller and in store statistics; filesystem operations cannot be forcibly cancelled by the store.

Alert evaluation bounds context, leader, rule, notification and incident callback waits. A pending physical callback retains its slot after timeout so it cannot overlap another invocation of the same callback. Close or replacement suppresses stale transitions and subsequent side effects. Notification sends have per-channel physical concurrency and a pending-callback cap; optional channel errors are reported without requiring an EventEmitter `error` listener. Owned cleanup is attempted even when a caller supplies a cancelled signal. Injected operations can keep their own resources active if they ignore cancellation. Redis bridge startup coalesces, and a subscription arriving after close is disposed without restarting bridge state; this is an injected-client contract check, not live Redis verification.
