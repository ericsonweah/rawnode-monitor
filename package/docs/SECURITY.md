# Security boundaries

Monitor observes application data. Treat its routes, metrics, traces and diagnostic bundles as sensitive. The runtime owns no server. Studio defaults to loopback-only authorization, validates socket address and loopback Host, rejects cross-origin fetches, uses header tokens or an injected authorizer, applies CSRF origin checks to custom authorizers too, rate limits requests and bounds SSE clients/queued bytes. `trustProxy:true` is an explicit deployment trust decision; do not enable it behind arbitrary forwarding headers. Origin/Host must be configured consistently with your reverse proxy. Token-authenticated page/asset requests require an authenticated proxy/session or custom authorizer to load the shell; native browser navigation does not send a bearer token automatically. No secret is embedded in HTML, URLs or persistent browser storage. The shell's in-memory token authorizes API fetches; token-required sessions poll because native EventSource cannot set a bearer header.

Remote ingestion is disabled by default. When enabled, the controller requires a configured HMAC secret, signature and bounded timestamp skew. The MAC covers the raw body and timestamp. This is authentication, not replay prevention: maintain nonce/deduplication policy at your ingress if you need exactly-once admission. Request limits apply to streamed, raw-buffer and preparsed bodies. Unexpected signal kinds are rejected; input cannot override measured queue byte accounting. Always set your HTTP server's header/body/idle deadlines; the injected router and server remain responsible for HTTP transport limits and pre-routing authorization.

Runtime emission, ended-span storage, public runtime health/snapshot/diagnostics, Studio JSON (including read, mutation, authorizer and ingestion failures) and bundles sanitize and redact. Failure details use the existing bounded serializer/redactor, omit stacks, and keep a safe HTTP status and sanitized code where possible; oversized records retain a small truncation marker. Cyclic and BigInt details remain serializable. Default redaction covers secret-like field names and known bearer/key patterns; it is not a universal detector of secrets embedded in arbitrary prose, URLs or unconventional field names. Add `security.secretKeys`, avoid collecting credentials, and review output before sharing. Low-level collectors/registries are application controls; direct raw objects may contain the values you supplied. Keep them private. Diagnostic argv capture is disabled unless explicitly requested. Bundle IDs reject traversal; the trusted configured output directory remains a filesystem authority. Protect it with appropriate ownership and avoid attacker-controlled symlinks.

Label count/value bounds, a 128-byte label-name bound, per-instrument/global cardinality and bounded queues prevent routine cardinality growth. Unknown signal kinds cannot grow runtime statistics. The serializer caps depth, arrays, keys, strings and actual JSON size; an oversize result becomes a small truncation record. User-defined getters, functions, regex patterns, callback sinks, plugins, storage/Redis clients and configuration are trusted code, not sandboxed inputs. Do not use this package as an isolation boundary for hostile JavaScript.

Network exporters and synthetics are opt-in. Configured destinations are trusted operator input, not user request fields. Enforce egress policy externally if monitoring destinations may be untrusted; no claim of general SSRF prevention is made. HTTP redirect handling prevents credential forwarding across origins and protocol downgrade where applicable. Redis/RawMongo are injected interfaces; no Redis/Mongo client implementation is bundled. TLS, server authentication, ACLs and deployment policy belong to the supplied client/environment.

The test fixture uses synthetic data on 127.0.0.1 with an ephemeral port. It never loads the original admin application or credentials. This preparation does not authorize publish, push, deploy, global install or daemon registration.
