# Migration, compatibility and versioning

The authoritative source is the local `www.firstprinciplelab.com/src/monitor` tree. `MONITOR_VERSION = '1.0.0'` is preserved provisionally; there was no Monitor-specific package manifest. This is a private candidate, not a claim that 1.0.0 has been released on npm. The owner has selected `@rawnode/monitor` and supplied organization/account ownership; administrative verification and the final public release version remain separate decisions.

Replace framework aliases with imports from `@rawnode/monitor` or documented capability subpaths. No imports resolve through `#monitor`, Foundation or sibling package aliases. Node-only ESM is the supported distribution; require/CommonJS, browser runtime core and bundler-specific targets are not promised. The Studio client is a separate browser export. No third-party dependencies, adapters, polyfills or vendor implementations are included.

Provide services explicitly through constructor options (`events`, `logger`, `database`, `redis`, `pm`, `unified`, `websocket`, `tcp`, `udp`) or create individual bridges. The optional `app` resolver path preserves existing Foundation container integration. The optional `/provider` retains bindings, readiness registration, middleware and commands while injecting `allowsBackgroundAutoStart(app)`; default provider boot does not start background work. Foundation's original policy helper, facade and migration remain preserved in the archive because they are app-owned.

Behavior corrections: close cancels startup and is terminal; invalid signal kinds reject; envelope metadata is sanitized; fake byte counts cannot bypass admission; span retention uses the configured limit; redaction applies at public telemetry boundaries; metric reset/remove frees keys; aggregate overflow stays within caps; resource removal cleans its health check; explicit EventEmitter subscriptions detach; synthetic removal suppresses stale results; body limits apply to pre-parsed inputs; custom auth does not bypass origin checks; partial durable writes fail; timed-out sink writes are not blindly retried. These changes may expose application code that relied on unsafe source behavior.

Preserved source declarations give named ESM exports complete visibility. Core runtime, health, resource, pipeline, PM and Studio contracts are strengthened. Some advanced extension declarations remain deliberately broad (`any`/`unknown`) as in the source; they are not a claim of exhaustive static validation. Runtime API manifests and the full source remain available for those extension points. No features were removed for missing type coverage.

Integration claims distinguish adapter contract tests from exact packed composition. PM's prepared `RawNodeRuntimeAdapter`/`RuntimeAgent` must expose `registerResource` and `unregisterResource`. `registerResource` can return a disposer or a fluent object. The bridge does not close PM-owned processes. Unified, Events, Logger and full Foundation live boot are unverified unless separately recorded in validation evidence.

The readiness pass corrects ratio sampling and async context binding. Applications may observe fewer spans at fractional sampling rates because the ratio now matches its configured value. HTTP middleware without a route template/resolver reports `unmatched` instead of a request-specific path. Health/resource replacement drops retired cached metadata/results. Studio Cancel performs no operator mutation; an intentional empty silence rule ID still means all rules. Pending exporter delivery rejects on direct close and cannot start later chunks/retries. Accepted file writes drain before close reports completion. Alert/notification callbacks now have bounded waits with documented controls and late-result suppression; non-cooperative external work can remain active.

Declarations now expose the existing runtime `TelemetryEnvelope` class (including `monitorVersion` and nullable metadata), `Tracer` construction/active APIs, and the actual options-object form of `Span.end`. This can reveal consumers that relied on inaccurate prior declarations; runtime symbol names and export-map entries remain unchanged.

The October 24 follow-up stops automatic HTTP replay after an acknowledgement timeout or a failed export with an acknowledged prefix. Callers now receive non-retryable errors with delivery uncertainty/progress details. This trades automatic recovery for avoiding silent duplicate delivery. Health registration/report and metric/synthetic declaration omissions are corrected without changing runtime exports.

Studio pauses automatic refresh during detail inspection and active filter/focus interaction. A visible Resume live updates control, manual Refresh or navigation restores live rendering. This preserves readable snapshots while leaving server state and the mount/destroy contract unchanged.

The October 25 continuation also treats truncated acknowledgements and transport failures after a completed payload write as uncertain, non-retryable delivery. HTTP `timeoutMs` now measures total elapsed time per request attempt instead of socket inactivity. Studio's non-JSON routes return sanitized JSON failures before headers are sent; errors after response start propagate to the host. Rejected rate-limit clients remain subject to the configured key-count bound. Public exports and declaration signatures are unchanged.
